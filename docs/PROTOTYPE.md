# 새김 프로토타입 범위

기준일: 2026-10-01 / Asia/Seoul

## 1. 배경과 검증 목적

사용자는 AI 설명을 읽을 때 이해되는 느낌은 있지만 시간이 지나면 잊는 경험에서 출발했다. 첫 버전은 전날 대화를 바탕으로 한 회상 질문이 도움이 되는지 확인한다.

개인화 데이터 구조와 자동 분석을 상세히 논의했으나, 검증 전에 범위가 커진다는 판단으로 보류했다. 즉각적인 정답률이나 주관적인 만족만으로 장기 기억 개선을 확정하지 않는다.

## 2. 합의된 사용자 경험

1. 하나의 대화 화면에서 질문하고 AI의 설명을 받는다.
2. 원문 대화를 저장한다.
3. 이후 접속 시 오늘 이전 최근 대화 날짜 기준 3일 범위에서 핵심 회상 질문을 최대 3개 만든다. 최근 하루 전체로 먼저 출제하고 질문이 0개일 때만 이전 날짜 전체를 누적한다.
4. 같은 대화 공간에서 한 문제씩 답하고 피드백을 받는다.
5. 힌트를 요청하거나 복습을 건너뛰고 일반 대화를 이어갈 수 있다.

화면은 단순한 대화 내역과 입력창이 중심이다. 별도의 지식 지도나 이해도 대시보드는 만들지 않는다. 질문 전에 전날 요약이나 정답을 먼저 보여주지 않는다.

최근 메시지를 우선 표시하고 과거 메시지는 추가 로딩한다. 과거 대화를 숨겨 회상을 강제하려는 것이 아니라, 로딩과 스크롤 부담을 줄이려는 목적이다. 화면에 표시하는 내역과 AI에 전달하는 맥락은 별개다.

## 3. 제안하는 최소 동작 규칙

아래는 구현을 시작하기 위한 기본안이며 아직 사용자와 개별 항목을 확정한 것은 아니다.

- 첫 접속 때 복습 여부를 확인하며, 별도 자정 배치나 외부 알림은 두지 않는다.
- 오늘 이전의 가장 최근 완료된 일반 대화 날짜와 그 이전 2일을 탐색한다. 복습할 미복습 근거가 없거나 회상할 학습 내용이 없다면 질문을 만들지 않는다. 생성 성공 후 질문이 0개인 경우와 생성 실패를 구분한다.
- 복습을 강제로 시작하지 않고 짧게 제안한다. 질문은 준비해두되 실제 진행은 사용자가 시작할 때 한다.
- 질문과 기대 답의 핵심, 근거 메시지 ID를 한 번에 생성한다. 기대 답은 답변 전에 클라이언트에 공개하지 않는다.
- 생성된 질문은 날짜별로 저장하고 새로고침 시 재사용한다. 중복 요청에도 질문 묶음이 중복 저장되지 않게 한다.
- 며칠 만에 접속해도 가장 최근 대화 날짜를 기준으로 3일만 탐색한다. 질문이 1개 이상이면 과거 날짜를 더 추가하지 않고, 질문이 0개일 때만 날짜 전체를 누적한다. 빈 날짜 때문에 범위를 늘리지 않는다.
- 일반 대화와 복습 메시지를 구분해서, 복습 자체가 다음 날 새 학습 내용으로 무한 재출제되지 않도록 한다. 답변 완료한 질문의 근거 메시지는 맥락으로만 포함하고 재출제하지 않는다. 같은 날짜의 미출제 내용은 후보로 유지한다.
- 선택한 날짜들의 누적 원문이 모델 입력 한도를 넘으면 조용히 잘라내지 않는다. 첫 버전에서는 제한과 대상 범위를 알리고, 별도 요약 파이프라인은 실제 필요가 확인될 때 추가한다.

## 4. 최소 저장 데이터 초안

정확한 테이블과 필드명은 구현 시 정한다. 핵심은 원문과 복습 기록을 중복해서 저장하지 않는 것이다.

| 데이터 | 최소 내용 |
| --- | --- |
| 메시지 | ID, 역할, 본문, 생성 시각, 일반 대화/복습 구분, 선택적 복습 질문 연결 |
| 날짜별 복습 | 접속일별 재사용 키, 탐색 기준 날짜, 실제 원문 날짜 범위, 생성 상태, 생성 시각 |
| 복습 질문 | 날짜별 복습 ID, 순서, 질문, 기대 답의 핵심, 근거 메시지 ID, 진행 상태 |

사용자 답변, 힌트, 피드백은 메시지로 저장하고 해당 질문과 연결한다. 별도의 사용자 지식 상태 테이블은 만들지 않는다. 중간 분석 문서나 단계별 추출 결과도 저장하지 않는다.

## 5. AI 호출 초안

- 일반 대화: 사용자 질문에 대한 답변 생성. 현재 맥락에 필요한 최근 대화를 전달한다.
- 복습 생성: 최근 하루 일반 대화로 먼저 출제하고, 질문이 0개일 때만 기준 날짜 이전 2일 안에서 하루씩 누적하여 다시 생성한다. 성공한 결과는 재사용하며 실패 시 재시도할 수 있다.
- 복습 진행: 현재 질문, 기대 답, 필요한 원문 근거, 사용자 응답으로 피드백 또는 힌트를 생성한다.

개인화 추출을 위한 별도 AI 호출은 없다. 일반 대화는 OpenAI Responses API와 기본 모델 `gpt-6-luna`를 사용한다. 최근 완료 메시지 최대 20개와 현재 질문을 전달하며 합계 60,000자를 넘으면 명시적으로 실패한다. 복습 생성은 선택한 날짜들의 완료된 일반 대화 전체를 대상으로 누적 60,000자까지 처리하며, 초과하면 범위와 한도를 알리고 실패 상태로 보관한다.

## 6. 구현 완료 확인 기준

- Docker Compose 환경에서 웹, API, MySQL을 실행할 수 있다.
- 실제 AI와 대화하고 새로고침 후에도 기록이 유지된다.
- 다른 날짜의 샘플 메시지나 테스트 시계로 다음 날 흐름을 확인할 수 있다.
- 최근 대화 날짜 기준 3일 범위에서 질문을 최대 3개 생성하고 같은 접속일 재접속 시 재사용한다.
- 한 문제씩 답변, 피드백, 힌트, 건너뛰기를 사용할 수 있다.
- 미복습 대화 없음, 범위 전체의 질문 0개, 생성 실패를 구분해서 처리한다.
- 날짜 경계, 중복 생성 방지, 저장 복원, 핵심 대화/복습 흐름을 검증한다.

## 7. 사용해보며 기록할 것

일주일 정도 직접 사용하며 질문의 적절성, 부담, 자발적 재사용, 도움이 된 순간을 짧게 기록한다. 며칠 뒤 다른 예제로 설명하는 것도 확인하되, 엄밀한 학습 효과 검증은 후속 과제로 둔다.

- 실제 사용에 맞는 모델·입출력 한도 조정 (현재 일반 대화·복습 모두 `gpt-6-luna`, 환경변수로 변경 가능)
- 개발 및 배포 시 접근 범위와 인증 방식
