# 새 Codex 프로젝트에서 시작하기

Codex에서 로컬 폴더 `C:\workspaces\saegim`을 프로젝트로 열고 새 채팅을 시작한다. 아래 프롬프트를 붙여넣으면 이 대화의 핵심 결정을 이어갈 수 있다.

## 시작 프롬프트

```text
새김(Saegim) 프로젝트를 이어서 진행하자.

먼저 AGENTS.md, README.md, docs/PROTOTYPE.md, docs/START_HERE.md를 읽어줘.

목표는 나 혼자 사용할 작은 웹 프로토타입이야. AI와 평소처럼 대화하고, 다음 날 전날 대화에서 만든 최대 3개의 회상 질문에 답하면서 이 경험이 학습에 도움이 되는지 검증하려고 해.

기술 스택은 Kotlin + Spring Boot WebFlux, Next.js + Tailwind CSS, MySQL, Docker Compose야. R2DBC를 기본 후보로 검토해줘.

UI는 단일 대화 화면과 입력창 중심이고, 복습도 같은 공간에서 진행해. 개인화 프로필, 지식 그래프, 개념별 이해도 분석 등은 이번 범위에서 보류했어.

우선 문서의 확정 사항과 제안을 구분해서 이해한 내용을 짧게 정리하고, 실제 구현을 시작하는 데 꼭 필요한 미정 사항만 확인해줘. 넓고 장황한 설계보다 한 번에 한 가지 결정을 다루자.
```

## 이후 구현 순서 제안

1. 환경과 의존성 호환성을 확인하고 AI 공급자 및 키 준비 방식을 결정한다.
2. 웹/API/MySQL의 최소 골격과 메시지 저장·조회부터 만든다.
3. 일반 대화의 실제 AI 응답과 단일 대화 UI를 연결한다.
4. 날짜별 질문 생성·재사용과 한 문제씩 진행하는 복습을 연결한다.
5. 날짜 경계, 실패 재시도, 새로고침, 과거 메시지 추가 로딩을 확인한다.
6. 로컬 실행법을 README에 갱신하고 직접 사용을 시작한다.

## 인계 시점 상태

- 프로젝트명과 기술 방향, 축소된 프로토타입 범위를 문서화했다.
- `apps/api`, `apps/web`, `compose.yaml`을 만들었다. 일반 대화의 저장·조회·OpenAI 호출·재시도 흐름을 구현했다.
- AI 공급자는 OpenAI API로 결정했고 테스트용 API 키는 준비되어 있다. 키는 서버 환경변수로만 사용한다.
- 기본 모델은 `gpt-6-luna`이며 환경변수로 바꿀 수 있다. 로컬 전용으로 실행하며 외부 인증과 배포는 정하지 않았다.
- Luna는 `reasoning.effort: none`으로 호출한다. 실제 일반 대화 응답과 복습용 Structured Outputs 질문 2개 생성을 확인했다. 이전 GPT-4.1 mini 검증 기록은 역사적 기록으로 유지한다.
- Java 21과 Docker Desktop WSL2 실행을 확인했다. 실행법과 검증 방법은 README를 읽는다.
- 날짜별 복습 생성·재사용, 한 문제씩 답변·힌트·피드백·건너뛰기와 상태 복원을 구현했다. `docs/REVIEW.md`에 현재 상태와 검증 결과를 기록했다.
- 다음 작업은 실제 사용에서 질문의 적절성과 부담을 확인하는 것이다. 기존 일반 대화 확인 결과는 `docs/IMPLEMENTATION.md`를 읽는다.
- 현재 구현을 초기 스켈레톤 기준점으로 Git에 기록한다. 원격 저장소는 https://github.com/jamm-king/saegim 이다. 외부 배포는 하지 않았다.
- 이전 개인화 다이어그램은 이번 프로토타입의 구현 명세가 아니다.
