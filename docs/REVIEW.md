# 최근 대화 회상 복습

2026-10-01 / Asia/Seoul

모델을 `gpt-6-luna`로 변경했다. 대화·복습 모두 `reasoning.effort: none`을 사용하며 도구를 활성화하지 않는다. 변경 후 백엔드 테스트와 빌드를 통과했고, 실제 일반 답변의 저장·조회·중복 요청 처리 및 샘플 원문의 복습용 Structured Outputs 질문 2개 생성을 확인했다. 샘플 복습 검증은 일반 DB에 저장하지 않았다. 아래 전체 복습 흐름 검증 기록은 변경 전 모델에서 수행한 결과이며, Luna의 실제 힌트·피드백과 전체 브라우저 흐름은 이번 변경에서 다시 실행하지 않았다.

## 현재 동작

웹 접속에서 `/api/review/prepare`를 호출한다. `Clock`을 한국 시간으로 해석하여 오늘 00:00 이전의 완료된 `CHAT` 메시지에서 가장 최근 날짜를 찾는다. 이 날짜와 그 이전 2일, 달력상 3일이 탐색 범위다. 오늘·미완료·실패·복습 메시지는 기준 날짜에서 제외한다. 각 날짜의 00:00 이상, 다음 날 00:00 미만을 UTC로 변환하여 조회한다.

최신 하루 전체를 먼저 전달한다. 질문이 1개 이상이면 즉시 준비 완료하고 이전 날짜를 추가하지 않는다. 성공했지만 질문이 0개면 이전 날짜 전체를 누적하여 다시 시도한다. 빈 날짜는 건너뛰되 탐색 범위는 늘리지 않는다. 생성 오류·근거 검증 실패·60,000자 누적 입력 한도 초과는 `FAILED`로 보관하고 재시도한다. 일부를 잘라내거나 실패를 질문 없음으로 간주하지 않는다.

`ANSWERED` 질문의 근거 메시지는 `alreadyReviewed` 표시를 붙여 원문 맥락으로 보존하고 재출제하지 않도록 안내한다. 서버도 이미 답한 근거 ID를 포함한 새 질문을 거부한다. 아직 출제되지 않은 같은 날짜의 내용은 다음 날 후보로 남는다. 후보 날짜에 미복습 assistant 근거가 없으면 AI 호출 없이 다음 날짜를 확인한다. 건너뛴 질문은 답한 것으로 처리하지 않는다. 학습 내용의 의미상 중복을 완벽히 판별하는 기능은 없고 메시지 근거 단위로만 방지한다.

OpenAI Responses API의 Structured Outputs로 질문·기대 답·근거 메시지 ID를 한 번에 생성한다. 최대 3개, 중복 질문 없음, 유효한 근거 ID 및 AI 설명 근거 포함을 서버에서 다시 확인한다. 기대 답은 원문에서 생성된 참고 기준이며 정확한 정답이나 사용자의 습득을 보증하지 않는다.

질문을 준비한 뒤 짧게 복습을 제안한다. 시작하면 한 문제씩 입력창으로 답하고 피드백을 받는다. 힌트를 요청하거나 오늘 복습을 건너뛸 수 있다. 질문 전 기대 답을 공개하지 않는다. 답변을 완료하면 다음 질문으로 진행하며 마지막 문제 후 복습을 마친다.

복습 메시지는 `REVIEW`로 구분한다. 질문에 연결된 사용자 답변·힌트 요청·AI 힌트·피드백은 기존 `messages`에 저장하며, 일반 대화 맥락과 다음 날 출제에서 제외한다. 별도의 지식 상태나 분석 결과는 저장하지 않는다.

## 저장 구조와 코드

- `review_days`: 접속일별 생성·진행 상태, 오류, 현재 질문 ID. 기존 `target_date`는 호환성을 위해 접속일의 전날 값으로 유지하며 실제 출제 날짜를 의미하지 않는다. UNIQUE 제약으로 하루의 성공 결과를 재사용한다. `anchor_date`는 탐색 기준 날짜, `source_start_date`·`source_end_date`는 실제 누적한 원문의 날짜 범위다. 기존 성공 묶음은 기존 `target_date`를 원문 범위로 보완하여 유지한다.
- `review_questions`: 순서, 질문, 기대 답, 근거 메시지 ID, 진행 상태. 날짜별 순서에 UNIQUE 제약.
- `messages`: 기존 구조에 `review_question_id`, `review_action`을 추가했다. 기동 시 기존 DB의 누락 컬럼만 추가하고 기존 대화는 보존한다.
- `ReviewDayRepository`, `ReviewQuestionRepository`, `MessageRepository`: R2DBC 저장·조회.
- `ReviewService`: 날짜별 준비, 시작, 다음 문제, 건너뛰기, 답변·힌트·재시도.
- `ReviewAi`: 출제용 JSON Schema, 근거·입력 한도 검증, 힌트·피드백 요청.
- `ReviewConfig`: 시계와 기동 시 스키마 보완. 스키마 보완은 기동 스레드에서 실행하며 런타임 이벤트 루프를 차단하지 않는다.

질문 묶음과 성공 상태, 답변·AI 응답·질문 완료 상태는 각각 DB 트랜잭션으로 함께 저장한다. 같은 요청 ID를 다시 보내면 기존 메시지와 응답을 재사용한다. 생성 도중 프로세스가 중단되어 `GENERATING`으로 남으면 다음 준비 요청에서 다시 시도할 수 있다. 로컬 단일 API 인스턴스에서 복습 변경 요청을 하나씩 처리하며 별도의 스케줄러나 큐는 두지 않는다.

## 상태 구분

| 상태 | 의미 |
| --- | --- |
| `NOT_PREPARED` | 해당 날짜를 아직 확인하지 않음 |
| `GENERATING` | 질문 생성 중, 중단 후 재시도 가능 |
| `NO_CONVERSATION` | 탐색 범위에 미복습 assistant 근거가 있는 완료 일반 대화 없음, AI 호출 없음 |
| `EMPTY` | AI 생성 성공 후 학습 내용에 맞는 질문 0개 |
| `FAILED` | 생성 실패, 이유 표시 및 재시도 가능 |
| `READY` | 질문 준비 완료, 시작 전 질문·기대 답은 공개하지 않음 |
| `ACTIVE` | 한 문제씩 진행 중 |
| `COMPLETED` | 모든 질문 답변 후 복습 마침 |
| `SKIPPED` | 오늘 복습 건너뛰기 |

성공·완료·건너뛰기 상태는 재접속 시 다시 생성하지 않는다. 공개 DTO에는 질문·진행 상태만 있으며 기대 답과 근거 ID는 반환하지 않는다. 과거 원문을 사용자가 직접 조회하는 기능은 유지한다.

## 최근 날짜 탐색 변경 검증 (2026-10-02)

- 백엔드 테스트 18개 통과: OpenAI HTTP 테스트 5개, 날짜·입력 한도·근거 검증 7개, 실제 MySQL 통합 시나리오 6개. 실패·건너뛴 테스트 없음.
- 실제 MySQL의 분리된 테스트 DB와 테스트 AI 서버로 접속 공백, 최신 하루 전체 포함, 오늘 제외, 질문 0개일 때만 날짜 누적, 최신 날짜 기준 3일 경계와 빈 날짜, 실패 후 재시도, 답한 근거 재출제 거부, 누적 입력 한도를 검증했다.
- 웹 테스트 8개, TypeScript 검사와 프로덕션 빌드 통과. API·웹 컨테이너를 다시 빌드하고 실행했다.
- Playwright Chromium에서 테스트 응답으로 날짜 범위와 데스크톱·모바일 배치, 가로 넘침 없음과 JS 오류 없음을 확인했다. 실제 서버에서는 기존 완료 상태와 날짜 컬럼 보완 결과를 확인했다. 실제 대화·복습 기록은 보존했다.
- 변경된 출제 프롬프트의 실제 OpenAI 응답 품질은 이번 검증에서 확인하지 않았다. 실제 AI 호출 없이 생성 분기와 저장·복원을 검증했다.

## 최초 복습 구현 당시 검증

- 백엔드 테스트 11개 통과: 기존 OpenAI HTTP 테스트 4개, 날짜·입력 한도·근거 검증 6개, 실제 MySQL 통합 시나리오 1개.
- 통합 시나리오는 테스트 AI 서버를 사용했다. 한국 자정의 대상 날짜 전환, 날짜 시작 포함·종료 제외, `REVIEW`·실패 대화 제외, 생성 성공 재사용, 질문 0개, 생성 실패와 재시도, 힌트, 답변 실패와 같은 메시지 재시도, 완료·건너뛰기, 다음 날 복습 메시지 제외, 잘못된 근거 거부, 입력 초과 시 AI 호출 안 함을 확인했다.
- 실제 OpenAI와 별도 MySQL DB에서 질문 2개 생성·힌트·피드백 성공. 원래 대화의 사본만 테스트 날짜로 조정했고 일반 대화 DB는 유지했다.
- Playwright Chromium으로 복습 시작·힌트·답변·새로고침 시 현재 질문과 완료 상태 복원·중복 답변 재사용·다음 질문·건너뛰기·일반 대화 복귀를 확인했다. API 응답에 기대 답과 근거 ID가 없는지 확인했고 브라우저 JS 오류는 0개였다.
- 웹 TypeScript 검사와 프로덕션 빌드 통과. 데스크톱 1280×900과 모바일 390×844의 배치를 확인했다.
- 대화 내역만 스크롤되고 복습 제어와 입력창이 아래에 유지되도록 정리한 뒤, 최종 데스크톱·모바일 화면에서 겹침 없음과 답변 완료 상태 복원을 추가 확인했다. 이 재검증에서는 AI를 호출하지 않았다.
- 검증용 API·웹 컨테이너와 두 테스트 DB를 정리했다. 일반 대화 DB에는 기존 메시지 2개가 그대로 남고, 실제 전날(2026-09-30) 복습은 `NO_CONVERSATION`이다. 소스·문서·예제 설정의 API 키 패턴 검사도 통과했다.

자동 테스트는 `scripts/verify-review.ps1`로 재실행할 수 있다. 실제 API 검증 보조 파일 `review-real-test.sql`, `review-real-smoke.ps1`, `review-browser.cjs`는 분리된 검증 DB·컨테이너를 대상으로 사용한다. 실제 AI 호출에는 사용료가 발생한다.

## 남은 확인

실제 하루가 지난 뒤의 사용 경험, 질문의 적절성과 학습 효과, 부담과 재사용 의사는 직접 사용하며 확인해야 한다. 실제 모바일 기기의 키보드 동작과 20개를 넘는 기록의 과거 페이지 UX는 이번 복습 검증 범위에 포함하지 않았다. 테스트 시계 `SAEGIM_TEST_NOW`는 평소 비워 둔다.
